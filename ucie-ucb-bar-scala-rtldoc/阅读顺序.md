# UCIe 项目代码阅读顺序

建议沿着一笔数据从 TileLink 进入、穿过 UCIe、再从 PHY 发出去的路径阅读。每到一层，先看顶层接口和连接，再逐行读子模块，并对照测试。

```text
TileLink 请求
  ↓
UcieTL：TileLink 接入和数据封装
  ↓
UcieDigitalTop
  ├─ ProtocolLayer
  ├─ D2DAdapter
  └─ LogicalPhy
  ↓
Phy / TX、RX lane 黑盒
  ↓
数字行为模型或 AMS 仿真模型
```

## 第一遍：建立整体地图

1. **顶层连接**：读 `scala/src/uciedigital/top/UcieDigitalTop.scala`。找出实例化的模块、`chipFacingIo`、`phyFacingIo`，以及 `protocolLayer → d2dAdapter → logicalPhy` 的连接。
2. **参数和接口**：读 `UcieDigitalTopParams.scala`、`interfaces/FDIInterfaceBundle.scala` 和 `interfaces/RDIInterfaceBundle.scala`。区分数据、状态和控制信号的方向，具体字段可以在后续使用时回查。
3. **完整测试的组装**：看 `scala/test/src/uciedigital/loopback/UcieDigitalLoopbackHarness.scala` 和 `UcieDigitalStagedBringupTest.scala`，了解端点如何连接、链路如何建立以及测试检查什么。

## 第二遍：从上往下逐层细读

4. **TileLink 接入层**：读 `scala/src/tilelink/TileLink.scala` 的 `UcieTL`。先定位 `managerNode`、`clientNode`、`UcieController`，再追踪 A 请求和 D 响应如何封装到主带数据。遇到分帧和流控时，读 `ValidFramer.scala` 和 `Credit.scala`。对照 `scala/test/src/tilelink/TileLinkSpec.scala`。
5. **协议层**：从 `scala/src/uciedigital/protocol/ProtocolLayer.scala` 出发，读 `ProtocolMainbandTx`、`ProtocolMainbandRx`，再看 `ProtocolStateController`。对照 `scala/test/src/uciedigital/protocol/ProtocolLayerTest.scala`。
6. **D2D adapter**：从 `scala/src/uciedigital/d2dadapter/D2DAdapter.scala` 看 FDI 和 RDI 之间的连接，再读主带、旁带模块，最后读 `AdapterSM` 和 `StallHandler`。对照 `scala/test/src/uciedigital/d2dadapter/D2DAdapterTest.scala`。
7. **Logical PHY 和训练**：从 `scala/src/uciedigital/logphy/LogicalPhy.scala` 顺着实例化关系进入子模块。先追主带数据，再看旁带通信和 link training。
8. **物理 PHY 边界**：读 `scala/src/phy/Phy.scala`，再看 `scala/src/phy/macros/Tx.scala` 和 `Rx.scala`。区分 Chisel 描述的逻辑和只有端口定义的 BlackBox。
9. **仿真模型**：先读 `verilog/README.md`，再按数字行为模型、`verilog/common/`、`verilog/models/eye/`、`verilog/models/circuit/` 的顺序阅读。可以先追一个 `tx_lane`，再看模拟驱动和接收阈值。

## 阅读每个模块时记录

1. 输入、输出分别连接谁？
2. 数据什么时候传输成功？例如 `valid` 和 `ready` 如何配合？
3. 保存了哪些状态，复位后是什么状态？
4. 哪些控制信号改变数据路径或状态机？
5. 对应测试给了什么输入、检查了什么输出？

建议先读 `UcieDigitalTop.scala` 和 loopback harness，画出模块连接图；然后从 `UcieTL` 开始追一笔 `Get` 请求。
