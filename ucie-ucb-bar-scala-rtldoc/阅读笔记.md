# 理解
### tilelink（非本项目，介绍）
#### TileLink 的几套功能级别

TileLink 定义了几套逐渐增加的功能，设备可以根据需要实现其中一套。一个简单的 UART 外设不需要实现多核 CPU 缓存一致性所需的全部逻辑。

| 级别 | 支持的主要能力 | 典型用途 |
| --- | --- | --- |
| TL-UL | 基本读写，例如 Get、Put | UART、GPIO、控制寄存器 |
| TL-UH | 在 TL-UL 基础上增加多拍传输、原子操作和提示等能力 | DMA、内存访问等 |
| TL-C | 在 TL-UH 基础上增加缓存块传输和一致性相关消息 | CPU 缓存与一致性互连 |

这里的 U 是 Uncached，C 是 Cached。例如，两个 CPU 都缓存了地址 X 的数据：当 CPU 0 要修改 X 时，TL-C 可以传递获取写权限、探查其他缓存等消息，帮助一致性控制器协调两边的缓存。具体一致性策略由系统设计决定。

#### TileLink 与 AXI 的主要区别

可以从三个角度看：

1. **功能范围**：TL-UL 大致可以类比 AXI4-Lite，TL-UH 可以和 AXI4 的普通内存访问场景比较，但它们不是一一对应的协议。TL-C 提供缓存一致性通信能力；标准 AXI4 本身不提供完整的硬件缓存一致性，Arm 的 ACE 在 AXI4 上增加了相关能力。

2. **通道组织**：TileLink 的普通读写主要使用 A、D 两个通道：A 发请求，D 返回响应；TL-C 还使用 B、C、E 传递一致性相关消息。AXI4 则按读写职责拆成五个通道：读地址 AR、读数据 R、写地址 AW、写数据 W、写响应 B。

3. **操作表达方式**：TileLink 在通道消息中用操作码区分 Get、Put、Acquire 等操作；AXI 则将读写请求分布在不同通道，并通过各通道上的控制字段描述事务。两者信号和事务规则不同，不能直接把接口接在一起，通常需要协议转换桥。

#### 直观示例

CPU 读 UART 状态寄存器，用 TL-UL 或 AXI4-Lite 这类简单接口就够了；两个 CPU 的缓存要协调对同一内存块的访问，则需要 TL-C，或者 AXI 加上 ACE 这类一致性能力。
